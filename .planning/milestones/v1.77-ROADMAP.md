# Roadmap: Aurora v1.77 Audit-Trail Integrity + API Contract Hardening

**Status:** Complete ✅
**Milestone:** v1.77 bug-fix + feature-enhancement sweep (fleet deep-dive findings)
**Started:** 2026-08-25

## Overview

Three verified production defects from the round-87 deep-dive, each turned
into a RED-regression → fix → full-suite-race-green loop:

1. **NFT burn destroyed its own audit trail.** Burn persisted the burn
   operation, then deleted the `nfts` row — and `nft_operations` declared
   `ON DELETE CASCADE`, so with `_foreign_keys=ON` (every write DSN) the
   cascade wiped *every* operation for the NFT inside the same transaction,
   including the just-saved burn op. The in-memory repo's long-standing
   contract (mint + burn retained, `GetNFT` nil) was silently violated on the
   real SQLite path: `nft history` and `GET /api/v1/nft/{id}/operations` came
   back empty after a burn.
2. **Token transfer history under-filled for multi-owner tokens.** The reader
   ran SQL `LIMIT/OFFSET` over *all* `token.transfer` events and then filtered
   the requested owner in memory, so with ≥2 transferring owners each page
   came back short (`limit=10 → 5`) and offset advanced through the whole
   token's stream, skipping the owner's own history. Separately the endpoint
   wrapped its array in `{"transfers":[...]}` — the only list endpoint to do
   so — which the web UI (`Array.isArray(data) ? data : data.data`) could
   never consume, so `token.html` history rendered empty forever.
3. **cmd/api silently ignored `config/aurora.toml`.** `config.Load()` set viper
   defaults + env bindings but never `ReadInConfig`, so the API binary ran on
   hardcoded defaults and ignored every `[server]/[log]/[db]` value operators
   placed in the config file — silent misconfiguration with no error.

## Deferred (Recorded Backlog Issues — future milestones)

Additional verified fleet-deep-dive findings from this round are **not** fixed
in v1.77 and are recorded in the graph for later:

- **ISS-088 — voting lifecycle has no transition guard:** an *ended* session
  can be re-opened to `active` (CastVote only rejects ended) and a *draft*
  session inside its time window accepts votes even if never started (the
  `session start` command is cosmetic). Should 409/400 on illegal transitions
  and reject votes pre-start.
- **ISS-089 — malformed base64 client input → 500 instead of 400:** token/NFT/
  voting use cases wrap `base64.DecodeString` errors in `fmt.Errorf` outside
  the classification table, so `owner=!!!` etc. hits the unclassified-500
  branch instead of a 4xx.
- **ISS-090 — oracle scheduler records `block_height=0`:** the continuously
  running fetch path never calls `SetChain`, so scheduler-written rows skip
  `chain.AddBlock` and diverge from the REST/CLI paths.
- (Also noted: unbounded NFT/lottery list endpoints, `token create --decimals`
  dead flag, `lottery reset` exit-0 without `--yes`, token/NFT TUI in-memory
  sandboxes, DB-path split-brain between migrate and the real stores.)
