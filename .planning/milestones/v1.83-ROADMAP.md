# Roadmap: Aurora v1.83 Config-Duration & Audit-Durability Sweep

**Status:** Complete ✅
**Milestone:** v1.83 bug-fix / feature-enhancement (ISS-110..112)
**Started / Closed:** 2026-08-27

## Overview

After v1.82 closed (report-the-truth & dead-code sweep), the graph had no
active tasks. A fresh deep-dive round plus the v1.82 hand-off notes surfaced
three verified defects / feature gaps, each traced through "evidence → root
cause → fix → verify":

1. **Bare numeric TOML durations were read as nanoseconds** (ISS-110,
   TASK-118). TASK-110 had fixed only `api.rateLimit.window`; `http.timeout`,
   `http.rateLimit.window` and `oracle.scheduler.checkInterval` were still
   read with raw `viper.GetDuration`, so `timeout = 60` in the config file
   silently became a **60ns** HTTP client timeout (every oracle fetch fails),
   `window = 10` a 10ns limiter window (silently disabled), and
   `checkInterval = 250` a 250ns scheduler ticker (busy-poll). Fixed with one
   generalized helper and regression tests.
2. **Failed post-commit audit publishes were reported but never healed**
   (ISS-111, TASK-119, the #1 v1.82 hand-off angle). v1.82 made a committed
   token op honest about audit-publish failure, but `SyncEventBus.Publish`
   was a synchronous in-memory fan-out whose only durability was the handler's
   autocommit INSERT at delivery time — a transient failure permanently
   dropped the audit record. Added the durable outbox (pending_events table +
   SaveIdempotent + AuditHandlerWithOutbox + OutboxDrainer) so a failed
   delivery is parked and retried with exponential backoff until it lands.
3. **Backup crash/failure-safety gaps** (ISS-112, TASK-120, round-95 backup
   deep-dive). Create's metadata.json was a plain os.WriteFile that could
   truncate on crash mid-write over new .db files; Restore O_TRUNC'd the live
   dest then io.Copy'd, so a mid-copy disk-full left a truncated .db at the
   live path. Both now use the same atomic temp-sibling + os.Rename promote
   primitive that Create's snapshot phase already used.

Parked with a recorded decision: ISS-084 phantom on-chain blocks (DEC-002 —
cross-DB atomicity redesign; token event trail already post-commit).

## Work items

1. **Numeric TOML durations = seconds everywhere (TASK-118, ISS-110,
   correctness).** Extract the TASK-110 fix into `config.DurationSeconds(key,
   fallback)`; route `http.timeout`, `http.rateLimit.window` (fetcher.go) and
   `oracle.scheduler.checkInterval` (config.go) through it. Bare numbers /
   numeric strings mean seconds; "1m"-style strings and Duration values pass
   through; zero/negative/garbage fall back. Regression tests at config level
   (all three keys + scheduler key) and fetcher level (`timeout = 60` → 60s).
2. **Durable outbox heals failed audit publishes (TASK-119, ISS-111,
   stability/feature).** `pending_events` table (event UUID as PK → idempotent
   enqueue + UNIQUE-safe retry), `SaveIdempotent` (INSERT OR IGNORE),
   `AuditHandlerWithOutbox` (parks on Save failure, returns nil unless even the
   park fails — the v1.82 do-not-retry semantics still hold), `OutboxDrainer`
   (bounded waves + exponential 1s→5m backoff). Wired: API server subscribes
   the outbox-wired handler and cmd/api/main.go starts a ticker drainer;
   CLI uses the outbox-wired handler + one DrainOnce in the service cleanup
   (CLI is short-lived). 7 new tests, events pkg 84.7% coverage.
3. **Backup atomic metadata + atomic restore destination (TASK-120, ISS-112,
   stability).** Create writes metadata.json via .tmp + os.Rename; Restore
   copies the archive to `<dest>.tmp` and renames into place (stale temps
   removed on every failure branch). Regression tests for both.
