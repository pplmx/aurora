# Roadmap: Aurora v1.81 Integrity, Audit & Client-Error Sweep

**Status:** Complete ✅
**Milestone:** v1.81 bug-fix / feature-enhancement sweep (ISS-096..106)
**Started / Closed:** 2026-08-27

## Overview

A four-agent deep-dive (domain, persistence, CLI, API) plus a follow-up
sweep surfaced a dozen verified defects. Two are genuine integrity flaws —
the lottery "VRF" verification was a no-op and on-chain audit records claimed
`block_height:0` — one is a concurrency data-loss path (racing token create),
and the rest are client-error classification, envelope-consistency, CLI
wiring, and configuration defects. All were root-caused, fixed with
regression tests, and verified with `go test ./... -count=1 -race` (34
packages) + `gofmt`/`go vet` clean.

## Work items

1. **Lottery VRF verification was a no-op (ISS-096, HIGH).** `VRFVerify`
   ignored the public key and never related the output to the proof or any
   key — it only checked output/proof length plus `proof[32:] ==
   hashToPoint(seed)` (fully public), so any 32-byte output selecting
   attacker-chosen winners with `proof = output ‖ hashToPoint(seed)`
   verified against *any* key. Replaced with a Schnorr-style NIZK
   (R₁‖R₂‖s, 96-byte proofs; deterministic per key+seed): verification
   checks `R₁ = s·G − c·pk` and `R₂ = s·H − c·output`, which together bind
   the output to the key. (TASK-104, commit 826023c)
2. **On-chain audit records claimed `block_height:0` (ISS-097, MEDIUM).**
   The usecases serialized their JSON before the chain assigned the height
   and stamped only the local DB copy. `AddLotteryRecord` now stamps the
   true height under the same lock that assigns it — one fix covers lottery
   create, oracle fetch/scheduler, and the TUI. (TASK-105, commit 6e77d01)
3. **Token create duplicate-symbol TOCTOU (ISS-098).** The pre-check ran
   outside the transaction and `SaveToken` used `INSERT OR REPLACE`, so two
   racing creates silently deleted the first token's row and balance.
   `SaveToken` is now insert-only (`ON CONFLICT(id) DO NOTHING` →
   `ErrTokenExists`), mirrored in the TUI in-memory repo. (TASK-106,
   commit 85bc43f)
4. **Every CLI error printed twice (ISS-099).** Cobra's default error print
   plus `Execute()`'s `❌ Error:` line. `SilenceErrors: true` now yields a
   single line. (TASK-107, commit a33dc88)
5. **`lottery create` default `--count` was always 0 (ISS-100).** The flag
   was registered with `viper.GetInt(...)` at `init()` before config
   loaded; the count is now resolved at run time from the configured
   `lottery.defaultCount` (3). (TASK-108, commit 8d6d52f)
6. **Backup Create destroyed prior snapshots on failure (ISS-101, HIGH).**
   `os.Remove(dest)` before `VACUUM INTO` plus a schema probe that
   materialized missing source DBs. Create is now two-phase (snapshot-all
   temps → atomic rename → metadata) and the probe no longer creates
   files. (TASK-109, commit 8831b14)
7. **Integer `api.rateLimit.window` became 60ns (ISS-102).** viper.GetDuration
   casts bare ints to durations, silently disabling rate limiting.
   `RateLimitWindow` now interprets numbers/numeric strings as seconds.
   (TASK-110, commit aef8110)
8. **Voting API 500'd on missing resources (ISS-103).** `sqlite.ErrNotFound`
   from the pre-transaction existence checks was unclassified. Mapped to the
   domain sentinels at all five sites (session/voter/candidate), producing
   the intended 404/400s. (TASK-111, commit dd13001)
9. **NFT mint accepted wrong-length keys; keys printed as raw bytes
   (ISS-104).** A short creator key minted an unburnable/untransferable
   NFT reported as success; responses emitted mojibake. `decodeKey` now
   enforces 32/64-byte lengths and DTOs base64-encode owner/creator/from/to.
   (TASK-112, commit after dd13001)
10. **CLI token audit events silently dropped (ISS-105).** `newTokenService`
    built a bus with no subscribers, so `token history` was always empty for
    CLI activity (the v1.73 ISS-080 fix wired only the API). The CLI now
    subscribes the audit handler. (TASK-113, commit 8ef9db1)
11. **Response-envelope inconsistencies (ISS-106).** Lottery history encoded
    no-rows as `null` instead of `[]`, and the 401 used a nested
    `{"error":{"code","message"}}` envelope. Both normalized to the flat
    shapes used everywhere else. (TASK-114, commit b9917e7)
