# Roadmap: Aurora v1.59 Metrics Records Recovered Panics

**Status:** Complete ✅
**Milestone:** v1.59 Metrics records recovered panics
**Started:** 2026-08-23

## Overview

The metrics middleware (registered last in `newRouter`) was the **innermost**
chi middleware, while `Recovery` was **outer**. When a handler panicked, the
panic unwound past the metrics middleware before `Recovery` caught it, so the
recovered 500 response was never counted in the request metrics — panic-generated
server faults were invisible in `/metrics` (http_requests_total, status
histograms, latency).

## Success Criteria

- [x] `metrics.Middleware` registered OUTER to `Recovery` (first in `newRouter`),
      so the metrics wrapper observes the whole inner chain including the
      recovered 500.
- [x] Regression test `TestMetrics_RecordsRecoveredPanicAs500`: a panicking
      handler returns 500 to the client AND increments `http_requests_total`,
      attributed to status 500.
- [x] `go build ./...` green; `go test -race ./...` green; `gofmt`/`go vet` clean.
