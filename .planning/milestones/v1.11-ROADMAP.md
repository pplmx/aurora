# Roadmap: Aurora v1.11 Lifecycle & Parity Coverage

**Status:** In progress
**Milestone:** v1.11 Lifecycle & Parity Coverage
**Started:** 2026-08-23

## Overview

v1.9–v1.10 closed API hardening and identity/authenticity gaps (ballot forgery,
NFT key↔owner binding, voting session lifecycle endpoints). v1.11 hardens the
*verification* of that surface: drive the newly-added session lifecycle and the
ended-session enforcement end-to-end through the real HTTP stack so regressions
in the parity/security work are caught by the suite, not by a misbehaving live
deployment.

## Success Criteria

- [ ] Extend the real-API voting smoke test to drive the session lifecycle
      over HTTP: create → vote → **end** (vote rejected on ended session) →
      **start** (fresh voter can vote) — proving the lifecycle endpoints and
      the v1.10 ended-session enforcement hold end-to-end.
- [ ] Full `go test -race ./...` green with the extended smoke test.
