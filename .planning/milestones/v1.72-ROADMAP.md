# Roadmap: Aurora v1.72 In-Transaction Nonce Deadlock (ISS-078)

**Status:** Complete ✅
**Milestone:** v1.72 fix the deadlock the v1.70 BEGIN IMMEDIATE change exposed in Transfer/TransferFrom
**Started:** 2026-08-25

## Overview

The v1.70 hardening (CHG-082) made every `db.Begin()` execute **BEGIN
IMMEDIATE** — the token transaction now holds the SQLite write lock from
`BEGIN` until commit. That immediately exposed a latent cross-connection
write that had been harmless under the old deferred semantics:

`Transfer` and `TransferFrom` called `ClaimNextNonce` **before** the
transaction (atomic UPSERT…RETURNING — already persisted), then re-saved the
same nonce **inside** the transaction via the replay store's `SaveNonce`. The
replay store opens its **own connection to the same file** (`aurora.db`) in the
API server wiring (server.go opens tokenRepo, eventStore and replayProtection
all against one DB — unlike the CLI wiring's separate `tokens.db` /
`nonces.db`). Inside the IMMEDIATE transaction the token connection holds the
write lock, so the replay connection's `SaveNonce` waited on a lock the
transaction could not release until `SaveNonce` returned — a self-deadlock
that tripped the 5s busy timeout into `SQLITE_BUSY` → spurious 500.

`TestTokenTransfer_HappyPath` and
`TestTokenNFT_Smoke_ApproveAllowanceAndNFTKeyBinding` failed 3/3 (~5s each) on
the v1.70 commit; both pass fast after this fix. The removal is
behavior-preserving: `ClaimNextNonce` already persisted the nonce, and a
rolled-back transaction still leaves the nonce consumed — the desired
conservative replay-protection behavior.

Audit of every remaining transaction body (token Mint/Burn/Create,
voting vote-creation, all NFT transactions) confirms none writes to the same
file through a second connection inside the transaction — each body goes
through `txRepo` only. The deadlock class is closed.

## Note for Future DSN Changes

`_txlock=immediate` on a DB is only safe when no code writes to that same
file through a **different** connection inside a transaction body. Any future
"share one SQLite file across stores" wiring change must re-audit every
transaction body for second-connection writes.
