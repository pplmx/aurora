# Roadmap: Aurora v1.8 Web UI Reliability

**Status:** In progress
**Milestone:** v1.8 Web UI Reliability
**Started:** 2026-08-23

## Overview

v1.7 (Web UI Parity) rebuilt the voting page and dashboard against the real
REST API, and fixed the response-DTO JSON casing (snake_case) to match the
documented convention. v1.8 hardens that work so the Web UI cannot silently
regress again and the coverage bar held by every other deliverable also
applies to the browser surface.

## Success Criteria

- [x] Web UI ↔ REST API **contract test** parses every `/api/v1/...`
      reference (with method) from `web/*.html` + `web/js/app.js` and asserts
      each resolves to a registered chi route (8c262db) — guards against the
      silent-404 regression v1.7's audit caught (`/voting/create` → 404).
- [x] Voting page performs real actions (register voter/candidate, create
      session, list sessions, list candidates, cast signed vote) (c014200).
- [x] Dashboard "Recent Activity" panel wired to real lottery + voting APIs;
      lottery history date column fixed (80e4353).
- [ ] Full `go test -race ./...` green with the new contract test in the suite.
