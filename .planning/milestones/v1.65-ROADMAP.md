# Roadmap: Aurora v1.65 Backup Self-Overwrite Guard

**Status:** Complete ✅
**Milestone:** v1.65 backup self-overwrite guard
**Started:** 2026-08-23

## Overview

`BackupService.Create` opened the destination at
`filepath.Join(output, name+".db")` with `O_WRONLY|O_CREATE|O_TRUNC` and then
`io.Copy`'d the source into it. The CLI maps the single DB under the name
`aurora` to the live path (`./data/aurora.db` by default), so running
`aurora backup create ./data` set `destPath == source` — `O_TRUNC` zeroed the
live database before `io.Copy` read it back as empty. No error, exit 0,
"Backup created": the operator's whole chain was silently destroyed.

`Create` now stats both files before the destructive open and refuses the
operation whenever `os.SameFile` reports the destination **is** the live
source — robust to `./data` vs `data` vs symlinked path aliases.

## Success Criteria

- [x] `aurora backup create <dir>` fails with an explicit "into itself" error
