# Roadmap: Aurora v1.86 Infra Robustness Deep-Dive

**Status:** In progress
**Milestone:** v1.86 robustness sweep (shutdown, security, resource bounds)
**Started:** 2026-08-28

## Overview

v1.85 fully drained the UX interactivity backlog. Round 100 ran a fresh
three-dimension parallel audit (API error-path, infra concurrency/scheduler,
CLI exit-code/output) and converted the top verified infra defects into
tasks. This milestone is the infra robustness sweep those audits seeded.

## Work items

1. **Cancellable oracle scheduler fetches (TASK-134, ISS-127, stability).**
   The scheduler's in-flight HTTP fetch used a background context with the
   10s client timeout, so `stopScheduler()` could not interrupt a pass under
   SIGTERM: shutdown stalled up to N sources × 10s, then `srv.Close()`
   closed the sqlite pool under the still-live fetch goroutine ("sql:
   database is closed"). Threaded a context through the whole fetch path
   (`Fetcher.FetchDataContext`, `FetchDataUseCase.ExecuteContext`,
   `Scheduler.Run/pass`) — an in-flight fetch aborts on cancel and no
   further source is fetched after shutdown, while the documented single
   initial pass on an already-cancelled context is preserved.
2. **Backup path-traversal rejection (TASK-135, ISS-126, security).**
   `Verify`/`Restore` joined metadata.Databases names onto `backupPath`
   unsanitized, so a crafted archive naming `../../victim` made it
   stat/hash/`sql.Open` arbitrary host `.db` files. Added
   `validateDatabaseName` (plain filename only) applied in Verify before any
   Join and re-applied in Restore's independent metadata read.
3. **Bounded rate-limiter buckets (TASK-136, ISS-129, security/stability).**
   Both the REST middleware `FixedWindowLimiter` and the fetcher
   `RateLimiter` grew a map key per client/source and never deleted it
   (`Reset` was unwired). `Allow` now sweeps fully-expired keys past a
   1024-threshold, keeping memory proportional to keys active within a window
   instead of every key ever seen.
