# Roadmap: Aurora v1.79 Silent-Input & Config-Correctness Sweep

**Status:** Complete ✅
**Milestone:** v1.79 bug-fix / feature-enhancement sweep (ISS-091..094)
**Started:** 2026-08-27

## Overview

Four observed candidates from the round-88 backlog were closed: three
silent-input/exit-code defects and the db.path split-brain. All were
small-to-medium, well-scoped, and covered by regression tests.

1. **`token create --decimals` was a dead flag (ISS-091).** The CLI flag
   (default "8") and `POST /token/create` both accepted a decimals value and
   silently dropped it — every token got `defaultDecimals=8` no matter what
   the caller asked, and garbage like `--decimals abc` passed silently.
   Decimals is now threaded end-to-end (`NewTokenWithDecimals` /
   `resolveDecimals`, domain `CreateTokenRequest.Decimals`, app request,
   optional `*int8` API body field, CLI `parseTokenDecimals`), with a usage
   error on non-integer/out-of-int8 input, and the TUI sandbox no longer
   resets decimals to 8 on mint/burn.
2. **`lottery reset` exited 0 when confirmation was declined (ISS-092).**
   Destructive reset without `--yes` printed a warning and returned nil, so a
   script that forgot `--yes` saw exit 0 and assumed the reset ran —
   contradicting the `backup restore --confirm` contract. It now refuses with
   a non-zero exit carrying the same warning; the test contract was updated.
3. **`GET /nft/list?owner=` was unbounded (ISS-093).** The endpoint returned
   every NFT an owner had with no limit/offset/caps, diverging from the v1.77
   owner-scoped paging on token history. It now parses/clamps `?limit`
   (default 20, cap 100) and `?offset` (cap 1000) at the handler, and the
   service/repo take `(owner, limit, offset)` with a stable `ORDER BY rowid`
   SQL page. CLI/TUI pass 0,0 and stay unbounded.
4. **db.path config split-brain (ISS-094).** `blockchain.DBPath()` was a
   hardcoded `./data/aurora.db` ignoring the documented `[db] path` in
   aurora.toml, while root.go's `migrate.autoRun` branch fell back to
   `$HOME/.aurora/data/aurora.db` — migrate and the stores could target
   different databases. A single `resolvedDBPath()` (viper `db.path`, default
   fallback) now drives `DBPath()`, `InitDB()`, and the autoRun migration, so
   every data path honors one configured location.
