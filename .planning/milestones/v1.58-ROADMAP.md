# Roadmap: Aurora v1.58 Lottery Reset Chain Re-seed

**Status:** Complete ✅
**Milestone:** v1.58 Lottery reset chain re-seed
**Started:** 2026-08-23

## Overview

`lottery reset` deleted the `blocks` and `lottery_records` DB rows but never
reset the in-memory blockchain singleton (created once by `InitBlockChain`'s
`sync.Once`). A post-reset `lottery create` therefore kept building on the
stale pre-reset blocks: the new draw's block height continued from the old
count (e.g. #3 after two prior draws) and its PrevHash referenced a block the
reset had deleted — a persisted-vs-in-memory height/prev-hash gap that
survived restarts.

## Success Criteria

- [x] New `BlockChain.ResetBlocks()` re-seeds the in-memory chain to a single
      genesis block (mutex-guarded, nil-safe).
- [x] `lottery reset` calls `ResetBlocks()` after clearing the persisted
      tables, so the next create restarts at block height #1 with a valid
      genesis PrevHash.
- [x] Regression tests: `TestLotteryReset_RestartsBlockHeightAfterCreate`
      (CLI: reset after two draws, then create reports `Block height: #1`) and
      `TestBlockChain_ResetBlocks_ReseedsToGenesis` (unit: appends then reset
      then append restarts at height 1).
- [x] `go build ./...` green; `go test -race ./...` green; `gofmt`/`go vet` clean.
