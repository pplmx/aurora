# Roadmap: Aurora v1.57 Lottery Stats Consistency

**Status:** Complete ✅
**Milestone:** v1.57 Lottery stats consistency
**Started:** 2026-08-23

## Overview

`lottery stats` counted draws from the in-memory blockchain
(`chain.GetLotteryRecords()`, backed by the `blocks` table), while every other
read command (`history`, `verify`, `export`, `import`) reads the persistent
`lottery_records` table. Imported draws write only `lottery_records` and never
reach the chain, so they appeared in `history` but never in `stats` — the two
commands disagreed on the same `Total lotteries` figure.

## Success Criteria

- [x] `lottery stats` reads the persistent `lottery_records` repository (same
      source as the other read commands) and reports `Total lotteries` and the
      highest recorded block height from that store.
- [x] Regression test `TestLotteryStats_AgreesWithHistoryForImportedRecord`:
      import a record, then assert `history` and `stats` both report 1 (and
      `Latest block: #N` matches the persisted height).
- [x] `go build ./...` green; `go test -race ./...` green; `gofmt`/`go vet` clean.
