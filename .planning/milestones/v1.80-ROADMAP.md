# Roadmap: Aurora v1.80 Phantom HOME Data-Dir Cleanup

**Status:** Complete ✅
**Milestone:** v1.80 bug-fix sweep (ISS-095)
**Started:** 2026-08-27

## Overview

A follow-up to v1.79's db.path cleanup: root.go's `PersistentPreRunE` still
ran the *other* half of the split-brain — a dead `app.Wire(dataDir)` wiring
that polluted the user's home directory on every CLI invocation.

**The bug (ISS-095):** `PersistentPreRunE` ran before **every** subcommand:
it resolved a `data.dir` (default `$HOME/.aurora/data`), mkdir'd it, and
called `app.Wire(dataDir)`, stashing the result in the never-read
`GlobalApp`. Empirically confirmed: even read-only `aurora version`
created `$HOME/.aurora/data` with an **unused** `tokens.db` / `events.db` /
`nonces.db` triple (plus WAL/SHM files) — a second token database that no
store reads, alongside the real `./data/aurora.db`. SQLite handles were
also left open for the process lifetime. Nothing ever read `GlobalApp`
(confirmed: only comments reference it).

**The fix (TASK-103):** remove `GlobalApp` + the `dataDir` computation/mkdir
+ the `app.Wire(dataDir)` call from `PersistentPreRunE`. The only remaining
pre-run work is the optional `migrate.autoRun` branch, which already targets
the same `blockchain.DBPath()` every store uses (v1.79). The now-dead
`data.dir` viper default and its test assertion were dropped; the
`internal/app.Wire`/`App` package remains (still covered by `wire_test`) but
has no production caller.
