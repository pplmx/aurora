# Roadmap: Aurora v1.56 Lottery Import Audit-Trail Integrity

**Status:** Complete ✅
**Milestone:** v1.56 Lottery import audit-trail integrity
**Started:** 2026-08-23

## Overview

`lottery import` persisted each accepted record via `repo.Save`, which uses
`INSERT OR REPLACE` keyed on the deterministic draw ID (sha256 of seed + VRF
output). There was no existence check, so re-importing an export file — or
importing one whose draw collides with an existing record — silently replaced
the stored draw, including its Verified flag and history. For an audit-trail
data store, that was an integrity breach.

## Success Criteria

- [x] `lottery import` checks `repo.GetByID` before `Save` and refuses to
      overwrite a draw that already exists (treated as a failed/colliding
      record, reported in the partial-failure output).
- [x] Fresh imports of records whose ID does not exist still succeed.
- [x] Regression tests:
      `TestLotteryImport_RefusesToOverwriteExistingDraw` (re-import into the
      same DB is refused, trail unchanged) and
      `TestLotteryImport_AllowsFreshValidImport`.
- [x] `go build ./...` green; `go test -race ./...` green; `gofmt`/`go vet` clean.
