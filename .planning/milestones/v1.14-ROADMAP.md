# Roadmap: Aurora v1.14 Observability Enrichment

**Status:** In progress
**Milestone:** v1.14 Observability Enrichment
**Started:** 2026-08-23

## Overview

v1.13 shipped a minimal stdlib Prometheus-text `/metrics` surface (request
total, per-status counter, latency histogram). Operators still cannot see
which subsystem a request touched, and the `/metrics` handler is not exported
as a reusable/server-mounted target for k8s/lb scraping. v1.14 enriches the
observability surface without pulling a metrics framework dependency.

## Success Criteria

- [x] Add a per-module request counter and per-module/per-status breakdown to
      the metrics registry, bucketing API routes by module (token, nft,
      voting, lottery, oracle) plus health/metrics/static buckets.
- [ ] Wire request IDs into request logs (optional correlation).
- [ ] Export the `/metrics` handler from the server for external scraping
      (documented, reuseable mount).
