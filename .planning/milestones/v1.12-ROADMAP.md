# Roadmap: Aurora v1.12 CLI/API Consistency

**Status:** In progress
**Milestone:** v1.12 CLI/API Consistency
**Started:** 2026-08-23

## Overview

v1.9 hardened the REST API surface (pagination caps, lifecycle endpoints,
token approve/allowance parity, snake_case responses). v1.12 closes the
remaining gap where the *CLI* bypasses those same safeguards: command-line
flags that feed the same repos/use cases as the API should honor the same
upper-bound and validation rules, so the hardening isn't specific to HTTP.

## Success Criteria

- [x] Cap CLI pagination flags to match the API handlers: oracle `data`
      `--limit` (max 100) and token `history` `--limit` (max 100) /
      `--offset` (max 1000) — prevents an unbounded DB scan via the CLI,
      mirroring v1.9 (6e6c660).
- [x] Reject negative oracle source `--interval` at the domain boundary
      (only `==0` is defaulted to 60; negatives were silently persisted).
- [x] Full `go test -race ./...` green.
