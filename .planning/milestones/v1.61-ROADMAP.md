# Roadmap: Aurora v1.61 Token Transfer-History Pagination

**Status:** Complete ✅
**Milestone:** v1.61 Token transfer-history pagination
**Started:** 2026-08-23

## Overview

`GetTransferEventsByOwner` passed `limit`/`offset` straight to
`GetByAggregate`, whose SQL `LIMIT/OFFSET` counted **all** events in the token
aggregate (mint + burn + transfer), and only then filtered for `token.transfer`
type and the owner in memory. For a token with interleaved mint/burn events, a
`limit=5` request could return fewer than 5 transfers, and offset pagination
skipped transfers — verified against the real SQLite store (`limit=5 -> 2`).

## Success Criteria

- [x] New `EventRepository.GetByAggregateAndType(aggID, eventType, limit,
      offset)` applies `LIMIT/OFFSET` over matching-type rows at the SQL layer,
      and `GetTransferEventsByOwner` uses it so pages are composed of transfer
      events only.
- [x] Regression test `TestGetTransferEventsByOwner_InterleavedTypesRegression`
      (real SQLite store): interleaved 20 transfers + 20 mints; `limit=5` now
      returns exactly 5 transfers, and offset pagination steps through
      transfers.
- [x] `go build ./...` green; `go test -race ./...` green; `gofmt`/`go vet` clean.
