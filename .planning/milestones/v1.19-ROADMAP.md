# Roadmap: Aurora v1.19 API Rate Limiting

**Status:** Complete ✅
**Milestone:** v1.19 API Rate Limiting
**Started:** 2026-08-23

## Overview

The REST API had no per-client rate limiting — any caller could hammer
endpoints unboundedly. v1.19 adds a config-gated, per-client fixed-window
limiter that rejects excess traffic with HTTP 429 + Retry-After.

## Success Criteria

- [x] Thread-safe fixed-window limiter keyed per client, with injectable clock.
- [x] RateLimit middleware returning 429 (+ Retry-After) on excess; wired into
      the protected /api group before auth, opt-in via `api.rateLimit.enabled`.
- [x] Limiter window-reset, per-client isolation, concurrency, and middleware
      429 tests.
