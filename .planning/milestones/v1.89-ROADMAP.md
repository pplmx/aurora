# Roadmap: Aurora v1.89 Web + TUI Detail-Polish Sweep

**Status:** Complete
**Milestone:** v1.89 web + TUI detail-polish sweep
**Started / Closed:** 2026-08-29 (rounds 109–113)

## Overview

Rounds 109–110 deep-dived the web frontend again and found a genuine,
user-breaking regression plus a context-advance gap; rounds 111–113 swept
docs/test-quality and the TUI surfaces with a fresh audit. Highlights:

- **Web Create Token was 100% broken.** The form POSTed
  `{name, symbol, total_supply}` with no `owner`, and the API runs
  `ValidatePublicKey` → `ErrPublicKeyRequired`, so every web create returned
  `400 PUBLIC_KEY_REQUIRED`. The CLI generates a fresh keypair for the
  owner; the web form had no field at all. Reproduced live against the real
  server (400 before, 200 after). (TASK-155, ISS-147)
- **Shared-context advance was applied only to NFT mint** (TASK-150). Token
  create (id+owner), voting session create (id) and lottery create (id) all
  left the next natural action needing a manual copy; token mint's auto
  `getBalance()` even errored against a blank owner. All advanced now, with
  an isolated `createOwner` field so a create key cannot leak into the
  Balance/History context. (TASK-156/157, ISS-148/150/151)
- **Docs + test gates**: AGENTS.md documented flags that don't exist (`nft
  get --id`, `voting session start -i`); synced. A JS syntax gate
  (`TestWebUIJS_SyntaxValid`, node --check, skip without node) stops a
  broken `web/js/app.js` from going green. (TASK-159/160, ISS-152/153)
- **TUI sweep**: `q` was untypeable in every form; token create ignored
  decimals; NFT mint accepted wrong-length owner keys; NFT transfer showed
  "Not found" on success; oracle sources cursor could step past the last
  row; lottery count parse silently defaulted to 3; `[T]`/`[D]` hotkeys
  ignored uppercase. All fixed with regression tests. (TASK-161..166,
  ISS-154..159)
