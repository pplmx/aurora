# Roadmap: Aurora v1.68 No Phantom Events on Token Tx Rollback

**Status:** Complete ✅
**Milestone:** v1.68 publish audit events only after the token transaction commits
**Started:** 2026-08-24

## Overview

`Mint` / `Transfer` / `TransferFrom` / `Burn` published their audit event
**inside** the `TxManager` transaction. The event bus writes to its own events
store (`events.db`), which a token DB (`tokens.db`) rollback cannot undo — so
when a later step in the same transaction failed (e.g. the atomic balance
primitive rejecting the losing side of a concurrent double-spend), the event
had already been persisted. `GetTransferHistory` then showed a transfer that
never happened.

The token state and the event store are **separate SQLite files**, so no
rollback could ever cover the publish. Publish is now issued **after**
`WithTransaction` commits successfully: a rolled-back transaction publishes
nothing, and an event-store outage surfaces as an error from the service
instead of aborting an already-committed value transfer.
