# Roadmap: Aurora v1.66 NFT Operation Audit-Trail Collapse

**Status:** Complete ✅
**Milestone:** v1.66 NFT operation audit-trail collapse
**Started:** 2026-08-23

## Overview

`nft.NewOperation` never assigned `Operation.ID`, so every mint/transfer/burn
row carried the PRIMARY KEY `""`. The SQLite repository persists operations
with `INSERT OR REPLACE INTO nft_operations (id, …)`, so each new operation
**replaced** the single `""` row: the whole per-NFT audit history collapsed to
the very last operation, and the on-chain block data
(`fmt.Sprintf("%s|%s", op.ID, op.Type)` = `"|transfer"`) was meaningless. The
domain unit test masked it by comparing two empty strings
(`ops[1].ID == op.ID`); the SQLite test masked it by hand-assigning distinct
IDs that the real path never produces.

`NewOperation` now assigns each operation a fresh `uuid.New()` (mirroring the
NFT id assignment), so the audit trail and on-chain records are per-operation.
