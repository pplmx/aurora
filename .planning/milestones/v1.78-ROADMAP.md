# Roadmap: Aurora v1.78 Client-Error Classification + Oracle On-Chain Recording

**Status:** Complete ✅
**Milestone:** v1.78 bug-fix sweep (round-87 backlog items ISS-089 / ISS-090; ISS-088 decided-not-a-bug)
**Started:** 2026-08-25

## Overview

Two verified production defects from the round-87 backlog were fixed, and a
third candidate was investigated, reverted, and recorded as a decision.

1. **Malformed base64 input returned 500 instead of 400 (ISS-089).** Every
   token/NFT/voting use case wrapped a `base64.StdEncoding.DecodeString`
   failure in an unclassified `fmt.Errorf`, so a client sending a syntactically
   invalid key/address (`owner=!!!`, `creator=!!!`, `private_key=!!!`) got
   `500 INTERNAL_ERROR` — polluting server metrics and hiding the actionable
   message. Each domain now defines `ErrInvalidBase64`; the app layers decode
   through a single `decodeKey` helper that wraps failures with it (one
   dispatch point instead of ~20 inline wraps); the handler classification
   table maps it to `400 INVALID_BASE64`.
2. **Oracle scheduler never recorded fetched data on-chain (ISS-090).** The
   continuously running `StartOracleScheduler` fetch used a nil chain, so every
   scheduler-persisted row skipped `chain.AddLotteryRecord` and stored
   `block_height=0`, diverging from the REST and CLI paths. The scheduler's
   fetch now calls `SetChain(blockchain.GetBlockChain())` like the handler;
   `FetchDataUseCase.Chain()` and a Server-stashed fetch make the wiring
   observable and regression-guarded.
3. **Voting "ended→reopen" was NOT a bug (ISS-088 → DEC-004).** An agent
   flagged that `POST .../start` after `end` re-opened a session (409→block).
   A first fix (TASK-096, `35d1365`) was reverted (`fc68119`) after the v1.10
   smoke test proved end→start reopen is the **documented lifecycle**: step 8
   ends a session, verifies a fresh voter is rejected, then starts it again
   and verifies the locked-out voter can vote. Voting is gated by the time
   window + per-voter already-voted + explicit `ended` status; `start` is a
   lifecycle/reporting action, not a hard gate. Recorded as DEC-004,
   governing the voting module; TASK-096 abandoned.
