# Roadmap: Aurora v1.54 Oracle SSRF TOCTOU Hardening

**Status:** Complete ✅
**Milestone:** v1.54 Oracle SSRF TOCTOU hardening
**Started:** 2026-08-23

## Overview

The oracle data fetcher validated a source URL host only at **add time**
(domain `AddSource`). The immediate fetch-time `http.Client` dial never
re-checked the initial request host — the redirect policy (`checkRedirectAllowed`)
only guarded *redirects*, and the SSRF block-list was not re-applied to the
initial target. Because add-time validation and the real dial can be separated
by minutes/days (or the record edited in the DB), a hostname that was public at
add time could be DNS-rebound to a loopback / RFC1918 / cloud-metadata address
by fetch time, and the fetcher would dial it — the classic SSRF TOCTOU.
