# Roadmap: Aurora v1.9 API Hardening & Deep Dive

**Status:** In progress
**Milestone:** v1.9 API Hardening & Deep Dive
**Started:** 2026-08-23

## Overview

v1.7/v1.8 made the Web UI real and reliable. v1.9 shifts focus back to the
API/domain surface, closing resource-exhaustion and correctness gaps surfaced
by repository deep dives, while keeping the race/coverage bar intact.

## Success Criteria

- [ ] Cap every user-supplied pagination/`?limit=` at an upper bound so a
      key-holding caller cannot force an unbounded DB scan (oracle `Query` +
      token `History` addressed; audit the rest).
- [x] Cap `?limit=` in oracle `Query` + token `History` (max 100) and
      `?offset=` in token `History` (max 1000) — prevents unbounded DB scans
      (3f570a4, c435ccb).
- [x] Enforce the `ended` session lifecycle on `CastVote`: an explicitly
      closed session rejects ballots even within its time window (was a
      no-op — the CLI `session end` had no effect on the API voting path).
- [x] Close token CLI↔API parity gap: added `POST /token/approve` and
      `GET /token/allowance` (the CLI and service had them; the REST API
      omitted both) (f5f3e92).
- [ ] Full `go test -race ./...` green.
