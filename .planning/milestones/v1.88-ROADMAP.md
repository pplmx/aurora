# Roadmap: Aurora v1.88 Web Error-Surfacing + Interactivity Polish

**Status:** Complete
**Milestone:** v1.88 web error-surfacing + interactivity polish
**Started / Closed:** 2026-08-29 (rounds 107–108)

## Overview

Rounds 107 and 108 audited the web frontend — the newest surface, only
partially covered since the round-97/102 polish sweeps. The round-97 contract
(TASK-124/TASK-141: check `res.ok` on every API call and surface failures via
the shared fixed banner) had enforcement gaps, and the two live surfaces
(dashboard, oracle) flickered their loading placeholders on every 15s
background poll. Round 107 closed the consistency + flicker gaps; round 108
added interactivity polish (burn-amount isolation, NFT mint context advance,
dashboard non-flickering refresh). All changes are client-side
(`web/js/app.js`, `web/oracle.html`, `web/token.html`); verified with
`node --check`, the shipped-asset web contract suite, and the full
`go test ./...` run (green before and after both commits).

## Work items

1. **Error-surfacing consistency (TASK-146, ISS-132/133/134, dx).**
   `blockchainApp.verify` was the only page still using raw
   `fetch + auroraHeaders()` instead of `apiFetch`, so a down/unauthorized API
   showed no shared red banner; it now goes through `apiFetch` like every other
   surface. Oracle `setEnabled`/`deleteSource` dropped blocking `alert()`
   dialogs for inline `sourcesError` text (the delete `confirm()` guard stays),
   and `query()` gained an inline `queryError` line instead of silently
   emptying the results table. Six dead `if (!res.ok)` guards in the voting
   app — unreachable because `apiFetch` already throws on non-2xx — were
   removed (registerVoter/registerCandidate/createSession/castVote/
   loadResults/sessionAction).
2. **Dashboard stat isolation (TASK-147, ISS-135, correctness).**
   `loadVoting` awaited candidates + sessions in one `Promise.all` with a
   single catch, so a transient failure on either endpoint dropped BOTH stat
   groups for that refresh. Split into `loadCandidatesStats`/`loadSessionsStats`
   with independent error handling — a failed card blanks only itself.
3. **Oracle 15s-poll flicker (TASK-148, ISS-136, dx).**
   `listSources`/`loadHealth` flipped `loading`/`loadingHealth` to true on
   every background poll, hiding the Data Sources + Feed Health tables and
   flashing "Loading..." every 15s. The placeholder gates now require an empty
   dataset, so existing rows stay visible during a refresh and the placeholder
   only shows while nothing has loaded yet.
4. **Token burn-amount isolation (TASK-149, ISS-137, dx).**
   The Burn form reused the Transfer `xAmount` model field, so a quantity
   typed for a transfer was pre-filled in the destructive Burn form and reused
   if the operator did not notice. Burn now has its own `burnAmount` state and
   `token.html` input binding — a transfer quantity can never leak into a
   destroy.
5. **NFT mint context advance (TASK-150, ISS-138, dx).**
   A successful mint left the Get/Transfer/Burn/History forms blank, forcing a
   manual copy of id + owner from the JSON result block. `mint()` now parses
   the response and advances `this.id`/`this.owner` to the freshly minted NFT,
   so the natural inspect/transfer/burn next step works immediately.
6. **Dashboard 15s-poll flicker (TASK-151, ISS-139, dx).**
   `refresh()` blank-reset the entire stats grid to 0/`-` and cleared Recent
   Activity at the start of every poll, so live cards dipped to empty and the
   activity list cleared + refilled each cycle. The stats grid is no longer
   reset (each loader overwrites its own card; a stale snapshot is better than
   a 0 blink), and the activity entries are collected per loader and swapped
   in atomically once all loads finish.
