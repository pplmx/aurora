# Roadmap: Aurora v1.60 API HTTP Timeouts

**Status:** Complete ✅
**Milestone:** v1.60 API HTTP timeouts
**Started:** 2026-08-23

## Overview

The API `http.Server` was constructed with only Addr/Handler — net/http leaves
`ReadHeaderTimeout`, `ReadTimeout`, `WriteTimeout` and `IdleTimeout` at zero,
so a client trickling headers or a body (slowloris / slow-body DoS) could hold
a handler (and its goroutine) open indefinitely, and idle keep-alive connections
were never reaped. That exposed the production API to resource-exhaustion DoS.

## Success Criteria

- [x] `cmd/api/main.go` now configures `ReadHeaderTimeout` (10s),
      `ReadTimeout` (30s), `WriteTimeout` (30s) and `IdleTimeout` (60s) via a
      testable `newServer` constructor.
- [x] Unit test `TestNewServer_SetsHTTPTimeouts` asserts all four timeouts are
      non-zero (no socket bound), plus the addr propagation.
- [x] `go build ./...` green; `go test -race ./...` green; `gofmt`/`go vet` clean.
