# Roadmap: Aurora v1.76 CLI Failure Exit Codes (ISS-083)

**Status:** Complete ✅
**Milestone:** v1.76 make CLI failures exit non-zero (no Run-only error-swallowing commands)
**Started:** 2026-08-25

## Overview

The `nft tui` and `oracle tui` subcommands were defined with **`Run:`** and
swallowed their failure inside `fmt.Println("Error:", err)`, never returning an
error. Cobra's `Execute()` therefore always saw `nil`, and the process exited
**0** even when the operation actually failed — a broken data dir, or
`/dev/tty` unavailable in a pipe/CI run, reported **success** to any
`$?`-checking script, and the error text corrupted stdout. Sibling commands
(`lottery tui`, `token tui`, `version`) already used `RunE`.

Both TUI commands now define **`RunE`** and return the error; cobra propagates
it to `Execute()`, which logs it and `os.Exit(1)`s with the message on stderr.

## Deferred (Recorded as Decisions)

Two verified fleet-deep-dive findings are recorded as issue/decision nodes
rather than fixed now:

- **ISS-084 / DEC-002 — phantom on-chain blocks on rolled-back txs.** Every
  mutator appends its `chain.AddBlock` before the domain transaction commits,
  so a lost race leaves a best-effort audit block. Deferred by decision: the
  block height must exist before the domain row save and the chain is a
  separate DB + in-memory singleton, so atomicity needs a cross-DB redesign;
  the token *event* trail is already hardened (post-commit publish, v1.68).
- **DEC-003 — API key embedded in served HTML** is accepted for the
  single-user local dev UI; CORS is locked to no-wildcard (v1.64) and the
  body cap + rate limiter bound blast radius. Documented future work in
  webauth.go.
