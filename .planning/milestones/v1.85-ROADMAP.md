# Roadmap: Aurora v1.85 UX / Interactivity / Usability Polish

**Status:** Complete ✅
**Milestone:** v1.85 polish (interactivity / usability / usability / ease-of-use)
**Started / Closed:** 2026-08-28

## Overview

User directed this milestone at visible UX polish — 细节优化, bug 修复,
打磨, 交互性, 实用性, 使用性, 易用性 — after v1.84 closed the voting
client-error sweep. Round-97 ran three parallel audits (TUI surfaces, CLI
ergonomics, web frontend) that surfaced a large set of concrete, verified
defects grouped by priority_score and user focus:

1. **Three of the four TUIs had untypable forms** (ISS-115, TASK-123). The
   lottery, token, and NFT TUI `Update` loops never forwarded keystrokes into
   their `textinput` models — a live user could not type participants, a seed,
   an address or an amount; Enter only ever produced a required-field error.
   The test suite drove values with `SetValue`, so the defect was invisible.
   Fixed by wiring per-view keypress forwarding + Tab/↑/↓ focus cycling
   (mirroring the oracle TUI's established pattern), plus lottery count bounds
   validation (a negative count panicked `make([]string, 0, count)` once
   typing worked) and comma-separated participant parsing (the input is
   single-line; `parseTextArea` previously split only on newlines). New i18n
   keys for the create-form errors (en + zh); hardcoded CJK routed through
   `GetText`.
2. **Web frontend silently swallowed API failures** (ISS-116, TASK-124).
   With a missing/expired API key, every list GET stored the `{error, code}`
   envelope into array state, rendering blank pages with zero feedback.
   Added a shared `apiFetch` that checks `res.ok`, extracts the error
   envelope, shows a fixed top banner and throws; all fetch sites route
   through it and keep list state as `[]` on failure. Form errors read
   `data.error` (the Go envelope) instead of the never-present
   `data.message`. Dropped redundant `x-init="init()"` on
   index/voting/oracle (Alpine 3.13.5 auto-calls `init()` — x-init fired it a
   second time, duplicating dashboard activity and doubling network calls).
3. **CLI `version` printed fabricated data** (ISS-117, TASK-125). It
   hardcoded "Version: 0.0.1" and `getGoVersion()` returned a fabricated
   "1.26+" (the real toolchain is go1.27.0) and ignored
   `-ldflags "-X main.Version=…"` entirely. Moved the command to
   `cmd/version.go` with link-time-overridable `cmd.Version`/`cmd.BuildTime`,
   prints `runtime.Version()`, and main.go's startup log reads the same vars.
   Verified end-to-end: ldflags-injected version appears in `aurora version`.

The audits also produced a backlog of additional verified issues
(ISS-118..ISS-125) recorded in the RIL graph for future rounds: dead "?" help
key in three TUIs, missing scroll bindings on viewport-backed history/list
views, hardcoded CJK bypassing i18n, oracle confirm-dialog selection
invisible, missing CLI confirmation gates on destructive ops (token/nft burn,
transfers, oracle source delete, migrate down), CLI help text resolved at
package-init before locale detection, unbundled Alpine from unpkg CDN without
SRI, and no refresh/polling on web lists.

## Work items

1. **TUI forms typable (TASK-123, ISS-115, interactivity).** Per-view
   keypress forwarding + focus cycling in lottery/token/nft; count bounds
   validation; comma participant parsing; i18n for create-form errors.
2. **Web API failure surfacing (TASK-124, ISS-116, ease-of-use).** shared
   `apiFetch` + banner + `[]`-kept array state + `data.error` form errors +
   duplicate-init removal.
3. **CLI version truthfulness (TASK-125, ISS-117, practicality).**
   ldflags-settable version/build-time vars, real `runtime.Version()`.
4. **Viewport-backed views scrollable (TASK-127, ISS-119, usability).**
   The history/list views in lottery/token/nft used a viewport but never
   forwarded key events to it — long content was clipped with no way to
   scroll. Handed key and mouse-wheel events to `viewport.Update` (which
   brings its native up/k, down/j, pgup/pgdn, space, b/f, u/d bindings).
5. **Confirmation gate on destructive CLI ops (TASK-126, ISS-122,
   safety/usability).** `token burn`, `nft burn`, `oracle source delete` and
   `migrate down` silently destroyed data; `backup restore --confirm` and
   `lottery reset --yes` already gated. Added shared
   `addConfirmFlag`/`requireConfirm` helpers and a `-y/--confirm` gate on
   all four commands (refused non-zero without it; existing tests updated to
   pass `--confirm`, new gate-refusal tests added).
6. **CLI --help localizes by locale (TASK-128, ISS-123, usability).** Cobra
   resolves Short/Long/flag help at package var-init, before
   `i18n.DetectAndInit()`; the lazy `GetTranslator` default was hard-locked
   to "en", freezing every `--help` screen in English regardless of LANG.
   The lazy default now adopts `DetectLocale()` and the lottery command's
   Long uses the new `lottery.long` key (en + zh).
